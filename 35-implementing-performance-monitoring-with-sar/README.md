# Implementing Performance Monitoring with sar

An enterprise-grade Linux performance monitoring and automated reporting project. This repository demonstrates how to configure `sysstat` and `sar` (System Activity Reporter) for continuous historical metric accounting, resource bottleneck analysis, automated report generation, and real-time terminal dashboards.

## 🛠️ Technology Stack & Tools Used

* **Operating System:** Red Hat Enterprise Linux / CentOS Linux

* **Monitoring & Accounting Suite:** `sysstat` (`sar`, `sadc`, `sa1`, `sa2`)

* **Automation & Scripting:** Bash Shell Scripting, Cron scheduling (`/etc/cron.d/sysstat`, `/etc/crontab`)

* **Benchmarking & Load Generators:** `stress-ng`, `dd`

## 📌 Executive Summary & Architecture

System Activity Reporter (`sar`) provides granular historical insight into kernel-level performance counters. In this project, automated background accounting was configured to record system state across CPU, memory, disk I/O, and network interfaces into `/var/log/sa/` binary logs. 

Custom Bash tooling was built around `sar` data streams to automate daily reporting, evaluate resource contention thresholds, and display a live monitoring dashboard for system operations.

## ⚙️ Step-by-Step Implementation & Analysis

### Phase 1: Service Configuration & Workspace Verification

1. Configured `/etc/sysconfig/sysstat` for extended metric retention (`HISTORY=30`) and disk accounting options (`SADC_OPTIONS="-S DISK"`).
2. Enabled and started the `sysstat.service` systemd unit.
3. Consolidated custom monitoring tools and analysis scripts into the central workspace directory.

### Phase 2: Resource Utilization & Report Generation

1. Executed live metric queries with `sar` across CPU (`sar -u`), Memory (`sar -r`), and Disk (`sar -d`) metrics under synthetic workloads generated by `stress-ng` and `dd`.
2. Generated automated summary reports highlighting kernel load averages, memory allocation percentages, and disk transfer rates.

### Phase 3: Real-Time Terminal Dashboard Execution

Implemented an interactive dashboard script (`performance-dashboard.sh`) that polls `sar` metrics every 5 seconds to present live operational status across system resources.

## 🎯 Conclusion

This project highlights a complete Linux performance monitoring architecture built on standard sysstat infrastructure. Key achievements include:

1. **Automated Historical Tracking:** Configured seamless background metric accounting to maintain 30-day historical performance logs for capacity planning and root-cause analysis.
2. **Operational Tooling:** Developed modular Bash scripts for isolated CPU, memory, storage, and network analysis, reducing manual troubleshooting time.
3. **Proactive Health Monitoring:** Created automated reporting and real-time dashboard visualization tools to immediately identify resource contention before system degradation occurs.

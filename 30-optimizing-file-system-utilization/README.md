## Executive Summary

This project demonstrates advanced Linux file system optimization and benchmarking across multiple storage configurations on Red Hat Enterprise Linux / CentOS 9 (`5.14.0` enterprise kernel). The objective was to configure, benchmark, and analyze high-performance storage configurations using **ext4**, **XFS**, and **Btrfs** (fallback mapping) to determine optimal mount parameters, I/O performance characteristics, and system resource overhead.

## Lab Implementation Steps

### Task 1 & 2: Advanced Mount Configurations & Tuning Parameters
Custom mount parameters were applied across each file system target to eliminate metadata write latency and improve sequential block throughput:
* **EXT4 Tuned (`/mnt/ext4-tuned`):** Mounted with `noatime,nodiratime,nobarrier,commit=60,stripe=64,data=writeback`.
* **XFS Tuned (`/mnt/xfs-tuned`):** Formatted with `agcount=4`, `logbufs=8`, `logbsize=256k`, and mounted with `noatime,nodiratime,attr2,largeio,inode64,noquota`.
* **BTRFS Workspace (`/mnt/btrfs-tuned`):** Mapped with optimized parameters `noatime,nodiratime`.

### Task 3: Performance Benchmarking & Resource Analysis
Three core scripts were written and executed inside the project scripts directory:
1. `filesystem_benchmark.sh`: Standardized tests evaluating 500MB sequential write/read speeds and 1,000 small file creation/deletion throughput.
2. `io_monitor.sh`: Captures device-level I/O metrics using `iostat -x` across active loop devices during a 100-file mixed I/O workload.
3. `resource_monitor.sh` & `generate_report.sh`: Evaluates CPU and memory consumption during intensive file compression/decompression tasks and consolidates system findings.

## Conclusion

1. **Mount Flag Optimization:** Disabling access time updates (`noatime,nodiratime`) and extending commit intervals (`commit=60`) provided immediate reduction in write latency and metadata overhead across all file systems.
2. **Workload Alignment:** 
   * **EXT4** demonstrated superior metadata performance during rapid small file creation and deletion tests.
   * **XFS** proved most efficient for continuous large-file streaming with low CPU overhead when tuned with enlarged log buffers (`logbsize=256k`).
3. **Enterprise OS Constraints:** Successfully handled RHEL/CentOS 9 kernel module restrictions by implementing fallback storage mappings, keeping testing pipelines operational without compromising benchmark script integrity.
